# 웹사이트 연결 (구독 서비스를 내 브라우저에서 쓰기)

ChatGPT·Claude·Gemini·Grok·Flow처럼 **구독으로 쓰는 웹사이트**를 FILM UNIT 작업에 쓰는 방법입니다. 사이트는 내 브라우저에서 내가 직접 열고, FILM UNIT과는 **복사 · 붙여넣기 · 파일 끌어놓기**로 주고받습니다. API 키가 필요 없고, 구독 요금 안에서 쓸 수 있습니다.

## 하지 않는 것

FILM UNIT은 이 사이트들에 **로그인하지 않고, 대신 조작하지 않고, 화면에서 결과를 긁어오지 않습니다.** 소비자용 구독 서비스의 약관은 API가 아닌 자동화된 접근을 제한합니다(OpenAI·Anthropic·xAI). 자동으로 로그인해 돌리면 계정이 정지될 수 있어 만들지 않았습니다. 로그인, 프롬프트 붙여넣기, 다운로드는 항상 사람이 합니다. 서비스 약관은 바뀔 수 있으니 각 서비스의 현재 약관을 확인하세요.

## 콘티 만들기 (글)

1. `00 · AI 모델`의 **콘티 감독**에서 **✋ 직접 붙여넣기**를 고릅니다.
2. `01 · PROJECT` 아래 **AI 감독**에 콘티 화면이 나옵니다. 열 사이트를 고르고 **열기 ↗**를 누르면 내 브라우저의 새 탭에서 열립니다. 로그인은 그 사이트에서 합니다.
3. **복사할 지시문**(코드 상자 오른쪽 위 복사 버튼)을 사이트의 **새 대화**에 붙여넣고, 사이트의 답을 통째로 복사해 아래 칸에 붙여넣은 뒤 **답 확인하고 받기**를 누릅니다.
4. 1단계는 이야기·화풍·인물·장소, 2단계부터는 샷 연출입니다. 샷은 12개씩 나눠서 차례로 묻습니다. 답이 형식에 맞지 않으면 이유를 알려 주고 아무것도 바뀌지 않으니, 같은 지시문으로 사이트에 다시 요청하면 됩니다.
5. 모든 샷을 받으면 **초안 검토**가 나옵니다. 검토하고 **제작 문서에 반영**을 눌러야 문서가 바뀝니다. API 모델로 만든 초안과 똑같은 검토 단계이며, 컷 타이밍·가사·가사 타이밍·검수·LOCK은 바뀌지 않습니다.

한 대화에서 계속 이어 가도 되고, 단계마다 새 대화를 열어도 됩니다. 지시문에 필요한 자료가 모두 들어 있어 새 대화가 오히려 안정적입니다.

## 이미지와 영상 가져오기

`00 · AI 모델`에서 이미지나 영상 모델로 **✋ 직접 만들기**를 고르면 `00 · 웹사이트 연결` 탭이 열립니다(API 모델을 골랐어도 **고른 모델과 상관없이 가져오기**를 켜면 씁니다).

- **인물·장소 참조**, **첫 프레임**, **샷 영상** 세 탭이 있습니다. 위쪽 표가 샷별로 무엇이 채워졌는지 보여 줍니다.
- 대상을 고르면 **붙여넣을 프롬프트**와 사이트에 **함께 올릴 참조 이미지**가 나옵니다. 사이트에서 만든 파일을 내려받으세요.
- 파일을 **끌어다 놓거나**, **다운로드 폴더 확인**을 눌러 최근 받은 파일에서 고릅니다. 폴더는 버튼을 누를 때 **한 번** 볼 뿐 계속 지켜보지 않으며, 원본 파일은 옮기거나 지우지 않습니다. 폴더는 `FILM_UNIT_DOWNLOADS`로 바꿉니다(기본 `~/Downloads`).
- 여러 파일은 빈 샷에 **순서대로 자동 배정**됩니다. 배정을 바꾼 뒤 **넣기**를 누르면 파일마다 결과가 나오고, 깨진 파일 하나가 나머지를 막지 않습니다. 같은 대상에 두 파일을 지정할 수는 없습니다.

가져오기 조건:

| | 형식 | 제한 |
| --- | --- | --- |
| 이미지 | PNG, JPEG, WEBP | 한 변 256px 이상, 6,400만 화소 이하, 40 MB 이하 |
| 영상 | MP4, MOV, M4V, WEBM, MKV | 0.5–60초, 500 MB 이하, 영상 스트림 필요 |

화면비가 프로젝트와 다르면 경고합니다(가져오기는 됩니다). 컴파일할 때 여백이 생기거나 잘릴 수 있습니다.

## 가져온 뒤

- 첫 프레임은 기존 `import-frame`과 같은 경로로 들어갑니다. 콘티가 바뀌므로 검토하고 **다시 LOCK**해야 합니다.
- 영상은 **초안(draft) 테이크**로만 들어갑니다. 승인된 결과로 취급되지 않으며 Preview에 쓸 수 있고, Final에는 기존 샷 검수가 필요합니다.
- 가져올 때마다 `render/handoff_log.json`에 시각, 종류, 대상, 사이트 이름, 원래 파일 이름, SHA-256이 기록됩니다.
- 사이트 이름은 어느 사이트에서 만들었는지 사람이 알아보라고 붙이는 표시일 뿐, 검증하지 않습니다.

## 한계

- 복사·붙여넣기와 파일 옮기기는 사람이 해야 하므로 API 모델보다 클릭이 많습니다.
- 사이트의 화면 구성, 구독 등급별 기능, 이미지·영상 정책은 자주 바뀝니다. 앱은 그 내용을 알지 못합니다.
- 사이트가 만든 이미지·영상의 이용 조건(상업적 사용, 워터마크 등)은 각 구독 조건을 따릅니다. 앱은 이를 확인하지 않습니다.
- 다운로드 폴더 확인은 파일 이름이나 시간으로 어떤 샷의 결과인지 알 수 없어, 순서 배정을 사람이 확인해야 합니다.
